# هم‌صدا (Hamseda)

کلاینت صوتی و متنی با ظاهر الهام‌گرفته از دیسکورد، برای سرورهای TeamSpeak 3. این پروژه با TeamSpeak یا Discord وابسته نیست و از نام یا دارایی‌های آن‌ها استفاده نمی‌کند.

## وضعیت: مرحله‌ی ۱ (رابط + پل)

- رابط سه‌ستونه‌ی دیسکوردی، تم تیره/روشن، فارسی و انگلیسی با RTL.
- پل Node.js با **حالت دمو** (داده‌ی ساختگی، بدون سرور) و **حالت ServerQuery** (فقط مشاهده).
- هنوز صدا و اتصال واقعی TeamSpeak نیست؛ این‌ها در مرحله‌ی ۲ می‌آیند. نقشه‌ی راه و معماری در سند پروژه توضیح داده شده است.

## اجرا

پیش‌نیاز: Node.js نسخه‌ی ۲۰ یا بالاتر.

```bash
npm install
npm run dev
```

بعد مرورگر را روی <http://localhost:5173> باز کن.

- برای امتحان بدون سرور: **امتحان دمو** را بزن.
- برای دیدن کانال‌های واقعی (فقط مشاهده): یک سرور TS3 خودت با ServerQuery، یا برای تست، یک سرور جعلی محلی:

```bash
npm run fake-query -w bridge    # در یک ترمینال جدا
```

و در برنامه: نوع اتصال `ServerQuery`، آدرس `127.0.0.1`، پورت کوئری `10011`.

## ساختار

```text
bridge/   پل Node.js (دمو، ServerQuery، سرور جعلی برای تست)
app/      رابط React + TypeScript + Vite
docs/     قرارداد پیام بین رابط و پل
```

## نکات امنیتی

- رمزها به‌طور پیش‌فرض ذخیره نمی‌شوند. اگر تیک «ذخیره» را بزنی، در مرورگر بدون رمزنگاری ذخیره می‌شوند.
- پل فقط روی `127.0.0.1` گوش می‌دهد و فقط از مبدأ رابط محلی قبول می‌کند.

## مجوز

هنوز انتخاب نشده. قبل از انتشار عمومی، شرایط استفاده‌ی TeamSpeak را بخوان.

---

## مرحله ۲: برنامه‌ی دسکتاپ (Tauri + هسته‌ی Rust)

ساختار جدید:

- `core/`: هسته‌ی Rust. اتصال به TeamSpeak 3 با `tsclientlib`، ساخت snapshot، و اکشن‌ها (جوین کانال، ارسال پیام، mute/deafen، قطع اتصال). ابزار تست: `hamseda-probe`.
- `src-tauri/`: پوسته‌ی Tauri. دو فرمان دارد: `connect_server` و `send_action`، و رویدادها را به پنجره می‌فرستد.
- `app/`: همان UI. داخل برنامه‌ی دسکتاپ از Tauri استفاده می‌کند، و در مرورگر همچنان از bridge در Node.

### اجرا (ویندوز یا مک یا لینوکس)

1. Node.js (نسخه ۲۰ یا بالاتر) و Rust را نصب کنید (`rustup`).
2. در پوشه‌ی پروژه: `npm install`
3. برنامه‌ی دسکتاپ را اجرا کنید: `npm run desktop`

### تست هسته بدون UI

```
cd core
cargo test
cargo run --bin hamseda-probe -- <آدرس سرور> <پورت> <نام شما> [رمز]
```

### محدودیت‌های فعلی

- در برنامه‌ی دسکتاپ فقط اتصال واقعی TeamSpeak فعال است. حالت دمو و ServerQuery فقط در مرورگر (با `npm run dev`) کار می‌کنند.
- اتصال واقعی به سرور هنوز روی یک سرور TeamSpeak زنده تست نشده است.
- پیام‌های دریافتی از سرور به کانال فعلی نمایش داده می‌شوند. پیام‌های خصوصی و سرورسراسری فعلاً در یک بخش مشترک (کانال ۰) ذخیره می‌شوند.
- پیام به کانالی غیر از کانال فعلی هنوز پشتیبانی نمی‌شود.
- آیکون برنامه موقت است و بسته‌بندی (`npm run desktop:build`) هنوز فعال نشده.

## گرفتن فایل exe ویندوز

**راه ۱ (بدون نصب چیزی):** پروژه را در یک ریپازیتوری GitHub خودتان (`main`) push کنید. workflow فایل `.github/workflows/windows-build.yml` را اجرا می‌کند و در تب Actions، بخش Artifacts، فایل `hamseda-windows` را دانلود می‌کنید که داخلش `hamseda-app.exe` است.

**راه ۲ (روی ویندوز خودتان):** Node.js، Rust (با rustup) و Visual Studio Build Tools (با کامپوننت «Desktop development with C++») را نصب کنید. سپس در پوشه‌ی پروژه:

```
npm install
npm run desktop:build
```

نصب‌کننده‌ی ویندوز در `src-tauri\target\release\bundle\nsis\` ساخته می‌شود (فایل `Hamseda_0.1.0_x64-setup.exe`). فایل exe خام هم در `src-tauri\target\release\hamseda-app.exe` است. برای اجرا به WebView2 نیاز دارد که روی ویندوز ۱۰ و ۱۱ معمولاً نصب است.

برای ساخت نصب‌کننده، دستور `npm run desktop:build` را بزنید (بدون `--no-bundle`).

## صدا (مرحله ۳)

- `core/src/audio.rs`: ضبط میکروفون و پخش صدا با `cpal`، رمزگذاری و رمزگشایی Opus (۴۸ کیلوهرتز، فریم ۲۰ میلی‌ثانیه)، و فیلتر ارسال.
- حالت پیش‌فرض **تشخیص صدا** است (آستانه‌ی ‎-45 dB). با `setTransmit` و `ptt` می‌توان به **فشار دادن برای صحبت** رفت. هنوز کلید میان‌بر در UI وصل نشده است.
- بی‌صدا (mute) میکروفون را قطع می‌کند و deafen پخش را ساکت می‌کند.
- اگر میکروفون یا بلندگو پیدا نشود، اتصال متنی ادامه دارد و پیام «Audio is off» نمایش داده می‌شود.

تست‌های واحد (بدون دستگاه صوتی): `cd core && cargo test`. تست واقعی صدا فقط با یک سرور TeamSpeak و میکروفون روی سیستم خودتان ممکن است.

محدودیت‌ها:
- میکروفون و بلندگو با هر نرخ نمونه‌برداری کار می‌کنند؛ تبدیل به ۴۸ کیلوهرتز خطی است و برای صدای گفتار کافی است.
- انتخاب دستگاه ورودی و خروجی هنوز نیست؛ همیشه دستگاه پیش‌فرض سیستم استفاده می‌شود.

### انتخاب میکروفون و بلندگو

در تنظیمات، بخش «دستگاه‌های صوتی» فهرست میکروفون‌ها و بلندگوهای سیستم را نشان می‌دهد. انتخاب «پیش‌فرض سیستم» یعنی همان دستگاهی که ویندوز یا مک به‌عنوان پیش‌فرض دارد. تغییرات بلافاصله روی اتصال فعلی اعمال می‌شوند.
