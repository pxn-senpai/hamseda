# هم‌صدا (Hamseda)

کلاینت دسکتاپ برای **TeamSpeak 3** با ظاهری شبیه دیسکورد و پشتیبانی کامل از فارسی (راست‌به‌چپ).
این پروژه با TeamSpeak یا Discord وابسته نیست و از نام، لوگو یا دارایی‌های آن‌ها استفاده نمی‌کند.
برنامه فقط یک کلاینت است: هر کاربر به سرور TeamSpeak خودش (یا سرویس عمومی) وصل می‌شود.

> Hamseda is a Discord-style desktop client for TeamSpeak 3 with a full Persian (RTL) UI.
> Core: Rust + tsclientlib. Shell: Tauri. UI: React + TypeScript.

## امکانات فعلی

**برنامه‌ی دسکتاپ (ویندوز، مک، لینوکس):**
- اتصال به سرور TeamSpeak 3 با آدرس، پورت، نام و رمز سرور. کادر آدرس می‌تواند `host:port` را هم بپذیرد.
- نمایش درخت کانال‌ها و کاربران، و ورود به کانال.
- ارسال و دریافت پیام در کانال فعلی.
- بی‌صدا (میکروفون) و کر (هدفون) کردن.
- صدا با Opus: حالت «تشخیص صدا» یا «فشار دادن برای صحبت».
- انتخاب میکروفون و بلندگو در تنظیمات.
- اگر سرور جواب ندهد یا کتابخانه‌ی اتصال خطا بدهد، سه بار تلاش می‌کند و بعد خطای کامل (با «Technical detail») نشان می‌دهد.

**نسخه‌ی مرورگر (بدون سرور):** داده‌ی نمونه‌ی داخل صفحه، برای دیدن ظاهر و امتحان دکمه‌ها. اتصال واقعی و صدا فقط در برنامه‌ی دسکتاپ کار می‌کند.

## تست‌هایی که انجام شده

- **اتصال واقعی:** در GitHub Actions به یک سرور TeamSpeak 3.13.7 وصل شد و درخت کانال‌ها گرفته شد (workflow: `e2e-teamspeak.yml`).
- **تست‌های واحد هسته:** ۱۱ تست برای پروتکل، ساختار درخت، صدا و Opus (`cargo test` در پوشه‌ی `core`).
- **نصب‌کننده‌ی ویندوز:** در GitHub Actions ساخته می‌شود (workflow: `windows-build.yml`).
- **رابط مرورگر:** میوت، دفن، تنظیمات، فرم اتصال و ارسال پیام بدون خطا تست شده‌اند.

## محدودیت‌های فعلی

- **صدا** روی دستگاه واقعی هنوز تست نشده است؛ فقط تست‌های واحد وجود دارند.
- **پیام‌های خصوصی و پیام سرورسراسری** در بخش مشترک کانال ۰ ذخیره می‌شوند. پیام به کانالی غیر از کانال فعلی هنوز پشتیبانی نمی‌شود.
- **کانال با رمز** هنوز پشتیبانی نمی‌شود.
- **ویژگی‌های دیسکورد** مثل پاسخ، ویرایش، حذف، واکنش، اشتراک صفحه و نقش‌ها هنوز پیاده‌سازی نشده‌اند.
- **ServerQuery** (حالت فقط مشاهده) فقط در نسخه‌ی مرورگر با پل Node کار می‌کند.

## اجرا

### نسخه‌ی مرورگر (توسعه)

پیش‌نیاز: Node.js نسخه‌ی ۲۰ یا بالاتر.

```bash
npm install
npm run dev
```

بعد `http://localhost:5173` را باز کن. دکمه‌ی **امتحان دمو** داده‌ی نمونه را نشان می‌دهد.

### برنامه‌ی دسکتاپ

پیش‌نیاز: Node.js، Rust (با `rustup`) و در ویندوز Visual Studio Build Tools با کامپوننت «Desktop development with C++».

```bash
npm install
npm run desktop
```

### ساخت نصب‌کننده‌ی ویندوز

```bash
npm run desktop:build
```

نصب‌کننده در `src-tauri\target\release\bundle\nsis\` ساخته می‌شود. یا می‌توانی بدون نصب چیزی، از تب **Actions** در GitHub فایل `hamseda-windows` را دانلود کنی.

### تست هسته و اتصال

```bash
cd core
cargo test
cargo run --bin hamseda-probe -- <آدرس سرور> <پورت> <نام شما> [رمز]
```

`hamseda-probe` وضعیت اتصال و درخت کانال‌ها را در خروجی چاپ می‌کند.

### نسخه‌ی مرورگر روی GitHub Pages

هر بار که روی `main` push شود، workflow ‏`pages.yml` نسخه‌ی مرورگر (با داده‌ی نمونه) را منتشر می‌کند. برای فعال بودن، در تنظیمات ریپازیتوری **Pages → Source → GitHub Actions** را انتخاب کن.

## ساختار پروژه

```text
core/           هسته‌ی Rust: اتصال TeamSpeak (tsclientlib)، صدا (cpal + Opus)، پروتکل پیام‌ها
src-tauri/      پوسته‌ی Tauri: فرمان‌های connect_server و send_action
app/            رابط React + TypeScript + Vite (فارسی و انگلیسی، RTL)
bridge/         پل Node.js برای نسخه‌ی مرورگر، و داده‌ی نمونه (دمو)
docs/           قرارداد پیام‌ها بین رابط و هسته
.github/        workflowهای ساخت ویندوز، تست E2E با سرور واقعی، و GitHub Pages
```

## نکات امنیتی

- رمزها به‌طور پیش‌فرض ذخیره نمی‌شوند. اگر تیک «ذخیره» را بزنی، در نسخه‌ی مرورگر بدون رمزنگاری در مرورگر ذخیره می‌شوند.
- پل Node فقط روی `127.0.0.1` گوش می‌دهد و فقط از مبدأ محلی رابط قبول می‌کند.
- در لاگ‌های CI یک سرور تست موقت (که بعد از هر اجرا حذف می‌شود) اطلاعات مدیریتی خودش را چاپ می‌کند. این سرور هیچ داده‌ی واقعی ندارد.

## مجوز و شرایط

هنوز مجوز انتخاب نشده است. قبل از انتشار عمومی یا استفاده‌ی گسترده، شرایط استفاده‌ی TeamSpeak را برای کلاینت‌های شخص ثالث و برای اجرای سرور بخوان. این یادداشت مشاوره‌ی حقوقی نیست.
