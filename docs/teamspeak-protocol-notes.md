# یادداشت پروتکل TeamSpeak 3 (از کد باز tsproto)

این یادداشت از کد منبع باز کتابخانه‌های `tsproto-packets` و `tsproto` (نسخه‌ی ۰.۱ و ۰.۲، لایسنس باز) نوشته شده است. ساختار رسمی نرم‌افزار TeamSpeak بررسی نشده است.

## ساختار هدر بسته‌ی UDP

| بایت‌ها | فیلد | توضیح |
|---|---|---|
| ۰–۷ | MAC | ۸ بایت. در بسته‌های init برابر `TS3INIT1` است. |
| ۸–۹ | packet id | عدد ۱۶ بیتی با ترتیب big-endian. |
| ۱۰–۱۱ | client id | فقط در بسته‌های client به server. در بسته‌های server به client نیست. |
| بعد از هدر | نوع و پرچم‌ها | یک بایت. نیم‌بایت پایین نوع بسته، نیم‌بایت بالا پرچم‌ها. |

محل بایت نوع: ۱۰ برای بسته‌های server به client، ۱۲ برای بسته‌های client به server.

## نوع بسته‌ها (نیم‌بایت پایین)

Voice، VoiceWhisper، Command، CommandLow، Ping، Pong، Ack، AckLow، Init.

## پرچم‌ها (نیم‌بایت بالا)

- `0x80` بدون رمزنگاری (Unencrypted)
- `0x40` فشرده (Compressed)
- `0x20` پروتکل جدید (NewProtocol)
- `0x10` تکه‌تکه (Fragmented)

## مراحل اتصال (init)

بسته‌های init با MAC برابر `TS3INIT1` شروع می‌شوند. مراحل در کد با این اسم‌ها آمده‌اند:

- سمت client: Init0، Init2، Init4
- سمت server: Init1، Init3

Init4 شامل سطح امنیتی هویت (`level`) و فرمان اولیه‌ی ورود است.

## بسته‌های command و صدا

- بسته‌های `Command` و `CommandLow` نیاز به `Ack` یا `AckLow` دارند. `Ping` با `Pong` پاسخ داده می‌شود.
- بسته‌های `Voice` و `VoiceWhisper` کدک صدا را مشخص می‌کنند. کتابخانه از کدک‌های Speex، CELT و Opus پشتیبانی می‌کند.

## ابزار تحلیل

برای تحلیل ترافیک زنده، `tshark` (بسته‌ی Wireshark) روی سیستم نصب شده است. داده‌ی ترافیک فقط از سروری گرفته می‌شود که خود ما یا کاربر اجازه‌ی آزمایش آن را داده است.

## محدوده‌ی این یادداشت

- فقط ساختار بسته و مراحل init از کد باز آمده است. منطق کامل رمزنگاری و فرمان‌های سرور در کتابخانه‌ی `tsclientlib` است.
- نرم‌افزار رسمی TeamSpeak مهندسی معکوس نشده است، چون شرایط استفاده‌ی آن تحلیل معکوس را منع می‌کند.
